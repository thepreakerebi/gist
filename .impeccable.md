# Design Context — Gist web demo

## Target audience

A capstone **defense panel and supervisor**: academics who will judge rigor, not
polish. They arrive skeptical and will probe. The interface has to make the
compression mechanism *legible* and the selected evidence *auditable* — every
claim on screen should be traceable to a timestamp in the source video.

Secondary: the same page is shown to peers and put in a portfolio afterwards,
so it should not look like a lab tool held together with tape.

## Use cases

1. Paste a YouTube link and watch it get ingested once (download → sample →
   transcribe → encode). Slow, one time, progress must be honest.
2. Return to a **library** of already-ingested videos and open one.
3. Ask questions in a **chat thread**, each answered in about a second from
   stored embeddings.
4. Inspect *why* an answer was given: the scored candidate field, the few
   selected pieces of evidence, and the actual video clip at that timestamp.

## Brand personality / tone

**Refined minimal, product-grade.** Quiet neutral palette, tight geometric
sans, near-invisible chrome. The video and the evidence carry the page. It
should read like a well-made commercial product rather than a research
prototype — confident, unfussy, nothing decorative that isn't doing work.

Light theme is primary. Dark follows the system preference; it is not the
default look and gets no glowing accents.

## The one thing to remember: **the collapse**

The thesis made visible. When a query runs, every scored candidate appears as a
mark on a time axis — hundreds of them. Then the selection lands and the field
*collapses*: unselected marks fade and drop away, the two or three survivors
rise and take the accent colour. That single moment is the argument the whole
project makes. Everything else on the page is arranged to give it room.

## Constraints

- Next.js 15 (this version has breaking changes — see `web/AGENTS.md`), React,
  Tailwind v4, shadcn/ui primitives already vendored in `components/ui`.
- Streams SSE from a FastAPI backend; must degrade gracefully when the API is
  down or an encoder is unavailable.
- Accessible: real focus states, reduced-motion honoured (the collapse becomes
  an instant state change), evidence readable without relying on colour alone.

## Explicit non-goals

- No Inter. No mono-as-shorthand-for-technical. No purple/cyan gradients, no
  glassmorphism, no identical card grids, no big-number hero stat blocks.
- No dark-mode-with-neon default.
